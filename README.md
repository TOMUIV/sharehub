## 这是什么

ShareHub 是一个轻量级自托管资源分享站：管理员在网页里把文件整理进目录树，访客无需任何账号即可浏览、搜索、下载。

它不做多用户、不做同步客户端、不做个人存储——只专注一件事：**管理员把内容放上去，访客拿链接就能下。** 适合课程资料、调研素材、团队资源库、素材分发站等场景。

## 核心特性

### 🎯 目录上下文上传
在某个文件夹里点上传，文件只进这个文件夹。上传进行中切到别的文件夹，已入队的文件依然归原文件夹，绝不串目录——可以一边传一边整理别处，连续上传互不干扰。

### ⚖️ 配额预留机制
在 init 阶段就按净增量预留容量（覆盖旧文件只算差值），而不是传完才发现超限。预留通过三路自动释放：取消即释放、空闲 2 分钟释放、关页立即释放。并发上传不会超配，可用空间始终准确。

### 📂 文件夹机制
支持整文件夹拖拽/选择上传，文件按大小升序排队（小文件优先），重名文件夹自动合并（同名覆盖、新文件并入）。

### 📊 实时状态可视化
四段容量条（已用 / 预留 / 缓存 / 可用）恒等加总；上传时各状态（总数 / 已完成 / 上传中 / 等待 / 暂停 / 失败）实时统计；文件与任务列表都支持分页跳转。

## 其他特性

### ⚡ 分片并发上传
大文件按 5MB 分片、3 路并发上传，每片带 SHA-256 完整性校验。速度快，也不受单次请求大小限制。

### 🔁 断点续传
断网、关页、取消后重新选择同一文件，只补传缺失分片，不重新传整个文件；≤64MB 的文件还能按内容哈希跳过已上传的部分。

### 🛡️ 安全
HMAC 签名 Cookie + 滑动续期 + HttpOnly/SameSite；路径防穿越；逐片哈希校验；管理接口全部强制登录。

### 🐍 单文件 · 零依赖
整个应用就是一个 `server.py`（Python 标准库），无数据库、无 Node、无 PHP。装得上 Python 3 的机器就能跑。

## 缓存与预留机制

**为什么有缓存？** 上传是分片的：分片先落到暂存区，全部传完再合并成正式文件。被取消或中断的分片不会立刻删除，而是保留为缓存——下次传同一文件可以断点续传。缓存有 10 分钟 TTL 自动清理，也可在后台手动「查看缓存 / 清理缓存」。

**为什么有预留？** 每个文件在 init 时就要通过容量校验。为防止多个并发上传各自通过校验、加起来却超限，服务器会为通过校验的文件预留容量（覆盖旧文件只预留差值）。预留有三种释放路径：

| 场景 | 预留去向 |
|---|---|
| 上传完成 | 文件进入池，预留释放 |
| 点取消 | 立即释放，分片保留为缓存（可续传）|
| 关页 | 立即释放（sendBeacon）|
| 崩溃/断网 | 空闲 2 分钟自动释放；分片缓存保留至 10 分钟 TTL |

## 快速开始

### 方式一：直接运行（零依赖）

把 `server.py` 和 `config.json` 放进你的部署目录（任意位置，例如 `~/sharehub`），然后：

```bash
# 需要 Python 3.8+
python3 server.py --host 0.0.0.0 --port 18888 --prefix ""
```

访问：
- 前台（免登录下载）：`http://你的主机:18888/`
- 后台：`http://你的主机:18888/admin`

> 路由是绝对路径，`--prefix` 只影响前端生成的链接。默认 `--prefix ""` 部署在根路径；经 nginx 部署在子路径（如 `/share`）时用 `--prefix /share`，见方式四。

### 方式二：Docker

镜像：**`tomthu/sharehub:latest`**

```bash
mkdir sharehub && cd sharehub
# 放一份 config.json 到当前目录（发布包自带模板），数据会存到 data/ 子目录
docker run -d --name sharehub \
  -p 18888:18888 \
  -v $(pwd)/config.json:/app/config.json \
  -v $(pwd)/data:/app/files \
  tomthu/sharehub:latest
```

或下载发布包（含 `config.json`、`docker-compose.yml`）后：

```bash
docker compose up -d
```

### 方式三：systemd（Linux 常驻）

把 `server.py` 和 `config.json` 放到你的部署目录（例如 `~/sharehub`），把 `share.service` 里 `ExecStart` 的路径改成你的实际路径，然后：

```bash
sudo cp share.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now share
```

### 方式四：nginx 反代（HTTPS + 子路径）

参考 `nginx.conf.example`。要点：`proxy_pass http://127.0.0.1:18888/;`（末尾斜杠剥离 `/share` 前缀，后端路由是绝对路径），容器以 `--prefix /share` 启动。分片上传务必设 `client_max_body_size 0`。

## 使用

**后台**（登录）：选择文件/文件夹上传、新建文件夹、多选打包 ZIP 下载/删除、查看缓存、清理缓存、查看日志、修改容量、修改密码。

**前台**（免登录）：浏览目录树、搜索当前目录、分页浏览、下载单个文件或打包 ZIP。

> **默认密码 `root`，登录后请立即修改。**
